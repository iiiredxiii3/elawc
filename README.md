# Smartlaunch Admin Pro — نسخه ۵

پنل مدیریت فارسی برای سرور SmartLaunch (وب + دسکتاپ). این نسخه به‌جای نمایش داده‌ی ثابت، به سرور وصل می‌شود،
همه‌ی ارتباط را لاگ می‌کند و هر خطا را روشن نشان می‌دهد.

## اجرا

```
npm install
npm run serve        # نسخه‌ی سبک: پنل روی http://127.0.0.1:3080
npm start            # نسخه‌ی Electron
npm test             # تست‌های پل (۲۱ تست، با سرور TCP آزمایشی)
```

پنل را **فقط از آدرس `http://127.0.0.1:3080`** (یا پنجره‌ی Electron) باز کنید. باز کردن مستقیم `index.html` کار نمی‌کند،
چون توکن امنیتی پل از سمت سرور به صفحه تزریق می‌شود.

## پیکربندی

فایل `smartlaunch.config.example.json` را به `smartlaunch.config.json` کنار برنامه (یا کنار EXE) کپی و ویرایش کنید،
یا از متغیرهای محیطی استفاده کنید:

| تنظیم | محیطی | پیش‌فرض |
|---|---|---|
| slHost / slPort | `SMARTLAUNCH_HOST` / `SMARTLAUNCH_PORT` | 127.0.0.1 / 7831 |
| httpPort / wsPort | `HTTP_PORT` / `WS_PORT` | 3080 / 8080 |
| eol (پایان هر دستور TCP) | `SL_EOL` | `\r\n` |
| httpBase (پروکسی تست REST) | `SL_HTTP_BASE` | خالی |
| logFile | `LOG_FILE` | خالی |
| bindHost | `BIND_HOST` | 127.0.0.1 |

اگر `BIND_HOST` را روی چیزی غیر از loopback بگذارید، `PANEL_PASSWORD` (Basic Auth) اجباری است.

## نکته‌ی مهم: پروتکل سرور باید کالیبره شود

دستورهای داخل کد (`ComputerLogin=...`، `ComputerLogout=...` و …) **قرارداد خود پروژه هستند و با مستندات رسمی SmartLaunch راستی‌آزمایی نشده‌اند**.
SmartLaunch برای ابزارهای جانبی API های XML/REST دارد و ممکن است پورت TCP سرور باینری باشد. برای کالیبره کردن:

1. پنل را باز کنید و تب **«کنسول»** را ببینید. هر داده‌ی دریافتی (متن یا hex) در لاگ `RX` نشان داده می‌شود.
2. با «TCP متن / TCP هگز / HTTP» دستور آزمایشی بفرستید و پاسخ را ببینید.
3. در **«تنظیمات پروتکل»** مشخص کنید: `handshake` (ورود)، `poll` (دستور لیست ایستگاه‌ها)، `prefix`، `map` (بازنویسی دستورها) و `timeUnit`.
4. پاسخ JSON (`computers[]` / `users[]`) یا خط‌های `Computer=3&Status=Busy&User=x&Time=3600` خودکار تفسیر می‌شود.
   تا وقتی لیست واقعی نیامده، بنر زرد و برچسب «داده نمایشی» دیده می‌شود.

مثال:
```json
{ "handshake": "LOGIN {user} {pass}", "poll": "GETCOMPUTERS", "pollSec": 5, "timeUnit": "sec",
  "map": { "ComputerLogin": "LOGIN_PC {value} {User} {Time}" } }
```

## رفتار در خطا
- بدون اتصال، عملیات **انجام نمی‌شود** (وضعیت UI عوض نمی‌شود) و خطا نشان داده می‌شود. فقط در «حالت شبیه‌ساز» عملیات محلی اجرا می‌شود و با برچسب SIM لاگ می‌شود.
- پیام‌های خطا برای ECONNREFUSED، ETIMEDOUT، رد احراز هویت، قطع پل و … جداگانه توضیح داده می‌شوند.
- ACK یعنی دستور روی سوکت نوشته شد؛ پذیرش واقعی در پاسخ سرور (`RX`) دیده می‌شود.
- لاگ را از تب کنسول می‌توان دانلود کرد.

## امنیت
- پل به‌صورت پیش‌فرض فقط روی `127.0.0.1` گوش می‌دهد؛ Origin بررسی می‌شود و پیام اول باید `HELLO` با توکن تصادفی باشد.
- رمز اپراتور فقط در حافظه‌ی مرورگر می‌ماند (برای `{pass}` در handshake) و ذخیره نمی‌شود. رمزی در کد نیست.
- **اگر رمز قبلی (`SL#9842!Kaviri`) واقعی بوده، آن را در SmartLaunch عوض کنید؛ در تاریخچه‌ی Git باقی است.**

## محدودیت‌ها
- ظاهر پنل به Tailwind CDN، Lucide و فونت Vazirmatn (اینترنت) وابسته است. بدون اینترنت پنل کار می‌کند ولی ظاهر ساده می‌شود.
- WOL فقط برای ایستگاه‌هایی کار می‌کند که MAC آن‌ها در پنل کنترل ایستگاه ثبت شده باشد (در مرورگر ذخیره می‌شود).
- لیست اکانت‌ها و بوفه هنوز داده‌ی نمایشی دارند تا وقتی سرور `users[]` بفرستد.
- EXE ها (pkg / electron-builder) در این محیط ساخته نشدند؛ workflow گیت‌هاب آن‌ها را روی ویندوز می‌سازد.
